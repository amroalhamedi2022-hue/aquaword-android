# AquaWord offline DOCX templates

Four editable **Word DOCX** templates are generated by `scripts/generate_templates.py` and copied to `android/app/src/main/assets/aquaword/` as part of native packaging. They are presented under **Document templates / قوالب المستندات** in the original Android document-browser overflow menu, not as disconnected ZIP attachments.

| Template | Scope |
| --- | --- |
| `research_en.docx` | English research-paper structure |
| `research_ar.docx` | Arabic research-paper structure, with actual OOXML paragraph RTL direction |
| `clinical_case.docx` | De-identified medical case report outline, differential and ethics prompts |
| `study_notes.docx` | High-yield notes, MCQ explanations and error log layout |

The user chooses one template, then chooses a **new document location** using Android Storage Access Framework. The source template remains untouched; no network access is needed. The generated document opens in native Collabora for editing.

Generator dependency: [python-docx](https://github.com/python-openxml/python-docx) **1.2.0 (MIT)**, used at GitHub build time and not bundled as an Android runtime dependency. No Word proprietary components are copied.

CI checks archive integrity, Office Open XML packaging, heading structure, A4 sizing, Arabic `w:bidi` / `w:rtl`, template IDs and Android integration syntax.

**What this feature does NOT mean:** automatic bibliography management, native APA/Vancouver citation insertion, embedded AI, or complete Word compatibility. These remain separate acceptance gates. A successful CI template check does not demonstrate a fully working Android APK.


## Guaranteed blank New Document

Besides the four selectable templates, `blank.docx` is an **empty** OOXML file packaged in `assets/aquaword/`. Native Writer New Document opens this asset for DOCX creation rather than assuming an upstream `templates/untitled.docx` was generated. Integration tests confirm an empty page and a valid package, desktop LibreOffice checks the round-trip, and APK verification compares the bundled bytes. Android runtime creation/save still requires device verification.
