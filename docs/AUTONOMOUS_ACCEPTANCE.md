## SAF DOCX truncation safety — 2026-10-23 (latest bounded source change)

- **Production change:** `scripts/apply_to_collabora.py` at `6377f7ad74811f3864850cde9319b670360358d1` changes native `LOActivity.copyTempBackToIntent()` so an existing DOCX is **never** overwritten with `ContentResolver.openOutputStream(uri)` / ambiguous mode `"w"`. Android documents that `"w"` **may or may not truncate**, so a shorter saved DOCX could retain trailing bytes from the original. Attempt `"wt"` first, then `"rwt"` only if the provider rejects the first explicit truncation mode. If both fail, the existing SAVE failure path reports failure and keeps the post-edit recovery attempt. No new dependency or engine rewrite.
- **Official API basis:** https://developer.android.com/reference/android/content/ContentResolver#openOutputStream(android.net.Uri) and https://developer.android.com/reference/android/content/ContentResolver#openOutputStream(android.net.Uri,%20java.lang.String). This is a data-integrity fix, not a claim of provider atomicity; provider-specific truncation behavior still requires device tests.
- **Test change:** `tests/test_overlay.py::AquaWordIntegrationTests::test_existing_saf_docx_save_never_uses_nontruncating_w_mode` at `935df41e409df0008981ba649bdd47563c843e27`. Runs the overlay twice against a fixture, checks only `wt` / `rwt` are present in the generated SAVE path, and verifies failure is not acknowledged as successful. **This is a source-level contract, not a real Android SAF-provider test.**

## Cloud SAF metadata cannot delay post-edit recovery — 2026-10-23

- **Production source changed: YES.** In `scripts/apply_to_collabora.py`, the native Writer SAVE checkpoint worker no longer performs `ContentResolver.query(OpenableColumns.DISPLAY_NAME)` before writing the recovery bytes. The previous query was moved off the callback thread but could still hang the **only** post-edit snapshot worker indefinitely when a remote SAF provider stalled. The worker now gets the name from app-private pre-edit history using `AquaWordHistory.preferredDisplayName(...)` and captures immediately. Unknown documents use a sanitized URI fallback. This preserves the original provider filename when a pre-edit copy exists and avoids an extra network IPC during SAVE.
- **Shared history core:** `history/src/org/libreoffice/androidapp/ui/AquaWordHistory.java` now resolves the latest pre-edit name by SHA-256 of source identity, never by a raw URI in metadata. Missing metadata returns a safe fallback without blocking save.
- **Tests added/updated:** Java history tests cover two distinct provider identities, missing/unsafe fallback names, and ignoring a later saved checkpoint's different label; Python overlay tests verify the native worker never queries a cloud provider, uses the local name helper, remains idempotent and preserves checkpoint-before-writeback order. Existing stale metadata-query source assertions were updated.
- **Official Android basis:** ContentResolver open/query calls may cross into a remote provider; Android ContentProvider is IPC-backed. No third-party library or license changes. Native upstream remains pinned at `2333344185931274f9c49d6c12a408cefcef6844`.
